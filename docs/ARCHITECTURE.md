# Architecture

How the app is put together and how to add a screen. Visual rules are in [DESIGN.md](DESIGN.md).

## Layout

| Path | What lives there |
|---|---|
| `src/routes/` | File routes (TanStack Router). `__root.tsx`, `login.tsx`, and `_app.tsx`, the authenticated shell that restores the session and loads `GET /auth/me` before any child renders. |
| `src/routes/_app/<name>*.tsx` | One route file per screen: `products/index.tsx`, `products/new.tsx`, `products/$productId.tsx`. |
| `src/features/<name>/` | A feature's components, hooks, zod schemas and column definitions. |
| `src/api/` | Typed client, session and token store, error model, idempotency keys, capability flags, generated OpenAPI types. |
| `src/lib/` | Permissions, query keys, nav registry, auth helpers, query client, toasts. |
| `src/hooks/` | Cursor lists, job polling, capability probe. |
| `src/components/` | `app/` (shell), `states/` (empty, error, forbidden, not found, not available yet), `data-table/`, `ui/` (shadcn). |
| `tests/e2e/` | Playwright specs against a live backend, one per area. |

`src/routeTree.gen.ts` is generated by the router plugin on `pnpm dev` and `pnpm build`. Commit it.

A new screen is a route file and a feature folder. Its nav entry is declared once in `src/lib/nav.ts`
and appears when the route exists, the role allows it, and its backend capability is live.

## Route template

```tsx
// src/routes/_app/products/index.tsx  (URL /products)
import { createFileRoute } from '@tanstack/react-router'
import { Page, PageHeader } from '@/components/app/page-header'
import { ProductsTable } from '@/features/products/products-table'

export const Route = createFileRoute('/_app/products/')({ component: ProductsPage })

function ProductsPage() {
  return (
    <Page>
      <PageHeader title="Products" description="…" actions={/* <Can action="product:import">…</Can> */ null} />
      <ProductsTable />
    </Page>
  )
}
```

Guarded routes (`/products/new` needs `product:import`, `/team` needs `team:manage`, …) wrap the page in
`<RequireAction action="…">` (renders `<Forbidden/>` in place, URL kept). URL search params: use
`validateSearch` with a zod schema (`@tanstack/zod-adapter` is installed). `/_app.tsx` has already
restored the session and loaded `/auth/me` before any child renders.

## API client (`src/api`)

```ts
import { api, unwrap } from '@/api/client'
const page = await unwrap(api.GET('/products', { params: { query: { limit: 50, cursor } } }))
const created = await unwrap(api.POST('/products', { body }))
```

- Paths are relative to `/api/v1` and fully typed from `src/api/schema.d.ts` (`V1Paths` in `src/api/types.ts`;
  `Schema<'ProductOut'>` for model types). Regenerate: `pnpm gen:api`.
- `unwrap()` returns `data` or throws `ApiError` (`type`, `status`, `message`, `details`, `errorReport`,
  `correlationId` = X-Request-ID, `retryAfter`). Network failures/proxy pages are `type: 'NETWORK'`, `status: 0`
  and raise the global "Can't reach the server" banner.
- Bearer token, `X-Request-ID`, refresh-on-401 (single flight within the tab and across tabs via Web Locks +
  BroadcastChannel) and replay are automatic. Never call `/auth/refresh` yourself.
- Idempotency (`products_bulk`, `imports_rows_retry`, `jobs_cancel`): `src/api/idempotency.ts`
  ```ts
  const intent = useIntentKey() // stable per user intent; intent.reset() after success / 409 IDEMPOTENCY_KEY_REUSED / new file
  api.POST('/jobs/{job_id}/cancel', { params: { path: { job_id } }, headers: idempotencyHeader(intent.get()) })
  ```
- Multipart (`/products/bulk`): pass a `FormData` as `body` (cast it, e.g. `body: fd as never`); the default serializer sends it as-is and the browser sets the boundary. Never set Content-Type.
- Endpoints the backend has not shipped yet answer 501. Keep them out of nav: `src/api/capabilities.ts` (`BUILT` flag + live probe), `useCapability(cap)`.

## Errors (`src/api/errors.ts`, `src/components/states`)

| Need | Use |
|---|---|
| Query failed | `<ErrorState error={q.error} onRetry={() => q.refetch()} />` (shows reference id; 501 becomes `<NotAvailableYet/>`) |
| Nothing loaded yet | `<EmptyState icon title description actions />` |
| 404 detail page | `if (isNotFound(q.error)) return <NotFound title="Product not found" backTo="/products" />` (treat 422 on a bad path id the same) |
| Role lacks action | `<RequireAction action>` / `<Forbidden/>` |
| Form 422 | `applyFieldErrors(err, form.setError, { prefix?, fields? })` maps `details[].loc` (drops `"body"`) to fields; returns unmapped details to toast |
| Specific codes | branch on `err.type` (`'SKU_CONFLICT'`, `'LAST_OWNER_REQUIRED'`, …), never on message |
| Toast | `toastError(err, title?)` from `@/lib/toast` (adds the reference + copy) |
| Helpers | `isNotImplemented`, `isNotFound`, `isForbidden`, `isRateLimited`, `isNetworkError`, `isInvalidCursor`, `describeError` |

Mutations toast errors globally (MutationCache). For inline handling (field errors, panels) pass
`meta: { toast: false }` to `useMutation`. Any 403 refetches `me` automatically so nav re-gates.
Query retry policy: network/5xx (not 501) twice, 429 after Retry-After, never other 4xx.

## Query keys (`src/lib/query-keys.ts`)

All keys start with `['t', tenantId]` (a tenant switch/logout clears the cache). Declared for every feature:

```ts
const keys = useKeys()
keys.me()                         keys.capabilities()
keys.products.list()              keys.products.detail(id)      keys.products.all()
keys.imports.detail(importId)     keys.importRows.list(importId, 'failed')   keys.importRows.all(importId)
keys.jobs.detail(jobId)           keys.marketplaceAccounts.list()
keys.rules.list({ marketplace, category })   keys.rules.all()
keys.members.list()
```

Invalidate every key a mutation affects. For example, after a bulk-import job ends:
`qc.invalidateQueries({ queryKey: keys.imports.detail(id) })` (prefix also covers its rows) and
`keys.products.list()`. Use `setQueryData(keys.products.detail(id), body)` to seed details after create.

## Permissions (`src/lib/permissions.ts`)

A copy of the backend role matrix (`apps/api/app/core/rbac.py` in the backend repo). The role comes from `GET /auth/me` only, never from the token. Update both together.

```tsx
const can = useCan()
{can('product:import') && <Button>New product</Button>}
<Can action="marketplace:connect"><Button>Connect</Button></Can>
```

Hide (not disable) actions the role can never take; still handle 403 from the server.
Session helpers (`src/lib/auth.ts`): `useMe()`, `useSession()`, `tenantName(me)`, `switchTenant(id)`, `logout()`.

## Lists and tables

```tsx
const keys = useKeys()
const list = useCursorList({
  queryKey: keys.products.list(),
  fetchPage: (cursor) => unwrap(api.GET('/products', { params: { query: { limit: PAGE_SIZE, cursor } } })),
})

const col = columnHelper<ProductOut>()           // module scope
const columns = col.columns([
  col.accessor('sku', { header: 'SKU', cell: (c) => <code className="font-mono text-xs">{c.getValue()}</code> }),
  col.accessor('title', { header: 'Title', meta: { className: 'max-w-80 truncate' } }),
])

<DataTable label="Products" list={list} columns={columns} getRowId={(p) => p.id}
  empty={<EmptyState title="No products yet" description="…" actions={…} />} />
```

`DataTable` (`@/components/data-table`) = TanStack Table v9 + skeleton rows, empty, error (with reference
+ retry), "Load more" (only when `has_more`), load-more error line, optional selection
(`enableRowSelection`, `selectionColumn<T>()`, controlled `rowSelection`/`onRowSelectionChange`), `onRowClick`,
`toolbar`. Invalid cursor (422 `["query","cursor"]`) resets to page 1 automatically. No server sort/search
exists: do not render sort arrows; a client filter must be labelled "Filter loaded rows".

## Async jobs

```ts
const { job, isTerminal, isWaitingForWorker, rateLimitedFor } = useJobPolling(jobId, {
  onTerminal: () => { qc.invalidateQueries({ queryKey: keys.imports.detail(importId) }); qc.invalidateQueries({ queryKey: keys.products.list() }) },
})
<JobStatusBadge status={job?.status} />   // @/components/app/job-status-badge
```

Backoff 1 s (first 10 s) → 2 s (to 60 s) → 5 s; stops at `succeeded|partial|failed|cancelled|dead_letter`;
pauses in hidden tabs; on 429 waits Retry-After. `onTerminal` fires once per job id.

## UI kit

shadcn/ui (radix, "nova" style) in `src/components/ui`. Badge has extra `success | warning | danger | brand | muted`
variants. Add components with `pnpm dlx shadcn@latest add <name>`, then restyle them to the tokens in
`src/index.css` (see DESIGN.md). Light and dark follow the system, with a toggle in the user menu and
⌘K. Page layout: `<Page>` + `<PageHeader title description breadcrumbs actions>`, and `<PageSkeleton/>`
while a whole page loads.

## End-to-end fixtures (`tests/e2e/fixtures.ts`)

```ts
import { test, expect, loginAs, loginViaUi, apiLogin, USERS, TENANTS, countRefreshes, visibleNavIds } from './fixtures'
test('…', async ({ page }) => {
  await loginAs(page, USERS.acme.operator, '/products')  // API login + hands mkos.rt to the app; no UI
})
```

`globalSetup` waits for `E2E_API_URL/readyz`. With `E2E_BACKEND_DIR` set it also empties the backend's
local rate limiter; otherwise `apiLogin` waits out `Retry-After` on 429. The backend's demo seed provides
`owner|operator|reviewer|admin@acme.test` and `@bharat.test`, one membership each. Use unique data per run
(`PW-<runId>-<n>`) and restore anything you mutate.
Dev-only hook: `window.__mkosTest.corruptAccess()` forces the next call to 401 (refresh tests).
